## 你希望的方式完全可行

## 上传步骤

1. 在自己的GitHub账户创建仓库，例如 `lazer-credential-artifacts`。将压缩包解压后，上传 `LaZer_V6_Companion/` **里面**的目录和文件，使 `README.md` 处于仓库根目录；不要只上传一个ZIP或只上传代码文件夹。
2. 完整包可使用本地Git提交。通过网页上传时，单文件较大或浏览器批量限制可改用Git；完整ZIP也可作为Release附件提供下载，不替代首页可直接阅读的补充材料PDF。
3. 检查仓库网页的README链接、补充材料PDF、SVG/PNG及源码是否可访问。若采用匿名评审，应按期刊要求控制公开时机和作者身份披露；这不是对当前整理工作的额外限制。
4. 创建固定标签 `paper-v6-artifacts-20261027`，发布同名Release，说明其对应正文V6与补充材料V6。后续修订另建版本，不移动本文对应标签。
5. 将真实仓库URL补入正文“代码与补充材料可用性”说明、仓库引用信息和Release描述。当前未给出实际仓库地址，本包不填写虚构URL或DOI。

## 建议的长期保存

GitHub作为统一访问入口已经满足上述用途。为提供长期引用，建议在固定Release基础上再通过Zenodo归档并取得该版本DOI；这与GitHub入口配合使用，不要求拆开补充材料和代码。GitHub官方说明支持连接Zenodo，并在每次发布Release时生成对应归档DOI。引用时同时给GitHub地址与该次固定归档DOI更清楚。

若期刊另有官方补充材料提交渠道，按期刊要求同时提交；不能假定期刊会自动转载GitHub内容。正式发表后可保留代码/数据/补充材料，并按出版协议确定仓库中正文PDF的可公开版本，更新正式论文信息。
